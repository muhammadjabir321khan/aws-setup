AWS-Setup Project File Guide

Beginner learning document — Purpose, Definition, and Improvements for every important file

Project: AWS-setup (Laravel + Docker + AWS ECR/ECS)
Region: eu-north-1  |  ECR repo: laravel-app  |  ECS: awsapp / awsapp

1. How the project works (simple picture)

Local development:
setup.ps1 / Makefile → Dockerfile.local → Docker on your PC + local MySQL

Production deploy:
buildspec.yml (AWS) or deploy.ps1 (your PC) → Dockerfile → push to ECR → ECS restarts app → app talks to RDS MySQL
Remember: An image is a packed snapshot of your app. A container is a running copy of that image. ECR stores images. ECS runs them.

3. File-by-file guide

3.1 buildspec.yml

Definition

A buildspec is AWS CodeBuild’s instruction file. It lists commands to run in the cloud when a build starts (like a recipe for automatic deploy).

Purpose

Automatically: install PHP/Node dependencies, build frontend assets, build the Docker image, push it to Amazon ECR, and force ECS to deploy the new image.

What it does (steps)
  1. install — Composer + npm packages
  2. pre_build — prepare Laravel for asset build, login to ECR (delete temporary .env so secrets are not baked in)
  3. build — npm run build + docker build
  4. post_build — docker push + ECS force new deployment
Improvements
  • Do not hardcode account ID / RDS details only in files — prefer CodeBuild env vars or Parameter Store
  • Add a health check wait after ECS update (confirm deployment success)
  • Run tests before building/pushing the image
  • Use immutable tags (git commit SHA) instead of only latest
  • Cache Docker layers carefully instead of always --no-cache (faster builds)

3.2 deploy.ps1

Definition

A PowerShell deploy script you run on your Windows PC to build and ship the production image manually.

Purpose

Same job as buildspec.yml, but local: build assets → Docker build → push to ECR → tell ECS to redeploy. Useful when CodeBuild is slow or you want a one-off deploy.

What it does (steps)
  1. Set AWS region, account, ECR repo, ECS names
  2. npm ci and npm run build
  3. Login to ECR
  4. Build and tag image
  5. Push image
  6. Force ECS update (warns if IAM blocks UpdateService)
Improvements
  • Fail the script if ECS update fails (today it exits 0 with a warning)
  • Add a -SkipBuild flag to only push/redeploy
  • Print the new ECS task public IP when ready
  • Support commit-SHA tags for safer rollbacks

3.3 Dockerfile

Definition

A Dockerfile is a recipe Docker uses to build an image: base OS/PHP, packages, config files, app code, and startup command.

Purpose

Create the production image that ECS runs: PHP 8.2-FPM + Nginx + Laravel app, configured for MySQL/RDS and production logging.

Key ideas inside
  • Production env vars baked in (APP_ENV, DB host, etc.)
  • DB_PASSWORD is NOT baked in — comes from ECS at runtime
  • Copies nginx/php configs and entrypoint.sh
  • Downloads RDS SSL certificate
  • Exposes port 8000
Improvements
  • Move DB host/username out of Dockerfile into ECS task definition / secrets
  • Use multi-stage build (build assets in one stage, slim runtime stage)
  • Avoid chmod 777 — use safer ownership and permissions
  • Run as non-root where possible
  • Add a HEALTHCHECK instruction

3.4 Dockerfile.local

Definition

A separate Dockerfile used only for local development containers.

Purpose

Give developers a PHP+Nginx box on their laptop. Code is usually bind-mounted from the host (so edits appear instantly). Opcache is off for easier debugging.

Difference from production Dockerfile
  • Uses php.local.ini and entrypoint.local.sh
  • Does not bake production RDS settings
  • Does not copy full app into image the same way (compose mounts code)
Improvements
  • Keep local and prod Dockerfiles closer (shared base stage) to avoid “works locally, fails in AWS”
  • Document required ports and env vars in comments at the top

3.5 setup.ps1

Definition

A Windows helper script with commands like setup, up, migrate, push.

Purpose

Make local Docker development easy without remembering long docker compose commands. Also includes production helpers (ecr-login, prod-build, push).

Common commands
CommandMeaning
.\setup.ps1 setupFirst-time local setup
.\setup.ps1 upStart containers
.\setup.ps1 migrateRun database migrations
.\setup.ps1 pushBuild + push ECR + ECS redeploy
Improvements
  • Align local DB name/password with docker-compose.local.yml (small mismatches confuse beginners)
  • Add status command showing container health
  • Add safer confirmation before production push

3.6 Makefile

Definition

A Makefile is a list of named tasks you run with make <task> (common on Linux/Mac/WSL).

Purpose

Same idea as setup.ps1, but for make users: make setup, make up, make push, etc.

Improvements
  • Keep Makefile and setup.ps1 in sync (same command names and behavior)
  • On pure Windows without make, document that setup.ps1 is preferred

3.7 docker-compose.yml

Definition

Compose file describing services (containers) and how they connect. This one is production-style.

Purpose

Run the production Dockerfile locally (without bind-mounting code) to test closer to AWS. Expects real DB env vars (often RDS).

Improvements
  • Clarify in README when to use this vs local compose
  • Optional: add a profile for local MySQL if needed

3.8 docker-compose.local.yml

Definition

Compose file for local development: PHP app + MySQL database.

Purpose

Start a full local stack. Mounts your project folder into the container so code changes are live. Uses healthcheck so PHP waits for MySQL.

Improvements
  • Keep DB credentials consistent across compose, entrypoint.local, and setup.ps1
  • Add a node service or document that npm runs on the host

3.9 docker/entrypoint.sh

Definition

The startup script that runs every time the production container starts (before the app serves traffic).

Purpose

Write/update .env from ECS environment variables (including DB password), fix storage permissions, start php-fpm and nginx, optionally run migrations.

Why it matters

Secrets like DB password should not live inside the image. Entrypoint receives them at runtime from ECS.

Improvements
  • Fail clearly if required env vars are missing
  • Separate migrate into a one-off ECS task (safer than migrate on every container start)
  • Reduce permission chmod breadth for better security

3.10 docker/entrypoint.local.sh

Definition

Startup script for the local development container.

Purpose

Create a local .env if missing, wait for MySQL, install Composer if needed, generate APP_KEY, start php-fpm + nginx.

Improvements
  • Match database name/password with compose defaults exactly
  • Print a clear “App ready at http://127.0.0.1:8000” message

3.11 docker/nginx/nginx.config

Definition

Nginx web server configuration for the container.

Purpose

Listen on port 8000, serve Laravel’s public/ folder, and pass PHP requests to PHP-FPM on 127.0.0.1:9000.

Improvements
  • Add gzip / caching headers for static assets
  • Tighten security headers (X-Frame-Options, etc.)
  • Hide nginx version in responses

3.12 docker/php/php.ini

Definition

PHP runtime settings for production image.

Purpose

Configure memory limits, upload sizes, timezone, error display, and opcache behavior for production.

Improvements
  • Turn display_errors Off in true production (log errors instead)
  • Tune opcache for production (validate_timestamps=0 when code is immutable in the image)

3.13 docker/php/php.local.ini

Definition

PHP settings for local development.

Purpose

Disable opcache, allow higher memory/time limits, show errors — better for debugging while coding.

Improvements
  • Optionally enable Xdebug behind an env flag for step debugging

3.14 docker/php/php-fpm.conf

Definition

PHP-FPM pool config (how PHP worker processes run).

Purpose

Run as www-data, listen on 9000, keep environment variables available to Laravel (clear_env = no), control worker counts.

Improvements
  • Tune pm.max_children based on ECS task CPU/memory
  • Add slow-log for requests that take too long
